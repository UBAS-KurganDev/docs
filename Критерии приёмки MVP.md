# Критерии приёмки MVP

## Назначение и статус

Документ определяет проверяемое поведение MVP поиска дешёвых авиамаршрутов. Основание — [описание MVP](mvp.md) и решения, принятые в интервью по приёмке. Подход к оценке городов описан в [«Метриках города»](<Метрики города.md>).

Критерии ниже фиксируют согласованные требования. Несогласованные параметры и правила перечислены в конце документа. Их отсутствие нельзя считать успешным прохождением соответствующей проверки.

## Условия проведения приёмки

Функциональные проверки выполняются на фиксированном контрольном наборе данных. Для каждого сценария заранее известны:

- города, относящиеся к ним аэропорты и часовые пояса;
- рейсы, расписания, предложения билетов и состав рейсов в каждом билете;
- цены, обязательные сборы, условия багажа и время получения цен;
- визовые расходы либо признак неизвестной стоимости;
- оценки промежуточных городов либо отсутствие ответа скрипта;
- курсы валют и текущее время, используемые в тесте;
- ожидаемые допустимые варианты и порядок их выдачи.

Каждый сценарий проверяется отдельно, чтобы ограничение выдачи десятью результатами не скрывало проверяемый маршрут. Если проверяется попадание конкретного допустимого маршрута в выдачу, данные должны обеспечивать ему место среди первых десяти.

Полнота поиска проверяется относительно контрольного набора. Для реальных данных она ограничена согласованным покрытием источников и поиска; это покрытие ещё предстоит определить. Требование найти десять лучших результатов не означает гарантию поиска самых дешёвых билетов на всём рынке.

### Параметры

| Параметр | Значение или правило |
| --- | --- |
| Направление | Только в одну сторону |
| Пассажир | Один взрослый, экономкласс |
| Паспортный профиль | Гражданин РФ с обычным загранпаспортом, без действующих виз и ВНЖ других стран |
| Максимальное окно поиска | 30 календарных дней, обе границы включены |
| Максимум промежуточных остановок | 3 |
| Максимальная длительность отдельной остановки | Не ограничена отдельно от общего окна |
| Начало проверки привлекательности | Остановка от 12 часов включительно |
| Минимальная привлекательность | Параметр `T`; рабочее значение не согласовано |
| Нет ответа скрипта оценки | Оценка города принимается равной 0 |
| Максимум результатов | 10 предложений, включая дубли |
| Валюта сравнения и выдачи | Российский рубль |
| Сортировка | По возрастанию рассчитанной суммы известных составляющих |
| Режим выдачи | Только после завершения всего поиска, без промежуточных результатов |
| Предельное время ответа | Определяется после измерений производительности прототипа |

## 1. Ввод и проверка запроса

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| INPUT-01 | Пользователь открывает форму поиска | Доступен ввод города отправления, города назначения, начальной и конечной дат. Авторизация не требуется |
| INPUT-02 | Не заполнено хотя бы одно обязательное поле | Поиск не запускается; ошибка показана у соответствующего поля |
| INPUT-03 | Выбран один и тот же город отправления и назначения | Поиск не запускается; отображается ошибка выбора города |
| INPUT-04 | Конечная дата раньше начальной | Поиск не запускается; отображается ошибка даты |
| INPUT-05 | Начальная и конечная даты совпадают, дата не в прошлом | Запрос допустим; поиск ограничен этим календарным днём |
| INPUT-06 | Начальная дата раньше текущей даты в городе отправления | Поиск не запускается; отображается ошибка даты |
| INPUT-07 | Начальная дата совпадает с текущей датой в городе отправления | Проверка даты не блокирует поиск |
| INPUT-08 | Диапазон содержит ровно 30 календарных дней включительно | Запрос допустим. Например, 1–30 мая |
| INPUT-09 | Диапазон содержит более 30 календарных дней включительно | Поиск не запускается; отображается ошибка диапазона. Например, 1–31 мая |
| INPUT-10 | У выбранного города несколько аэропортов в контрольных данных | Поиск учитывает все эти аэропорты; выбор конкретного аэропорта от пользователя не требуется |
| INPUT-11 | Пользователь выполняет поиск | Применяется фиксированный профиль пассажира; форма не запрашивает число пассажиров, возраст, класс обслуживания, гражданство, визы или ВНЖ |

## 2. Даты, длительности и структура маршрута

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| ROUTE-01 | Есть допустимый прямой рейс | Он участвует в общей выдаче наравне с маршрутами с остановками |
| ROUTE-02 | Варианты содержат 1, 2 или 3 промежуточные остановки | Каждый может участвовать в выдаче при выполнении остальных условий |
| ROUTE-03 | Вариант содержит 4 промежуточные остановки | Он исключается из выдачи |
| ROUTE-04 | Есть единый билет на несколько рейсов и маршрут из отдельных билетов | Оба типа предложений поддерживаются |
| ROUTE-05 | Вылет из исходного аэропорта приходится на 00:00 начальной даты по его местному времени | Вылет соответствует окну поиска |
| ROUTE-06 | Прибытие в конечный аэропорт происходит в последний день окна по его местному времени | Прибытие соответствует окну поиска |
| ROUTE-07 | Исходный вылет раньше начальной даты либо конечное прибытие позже конечной даты в соответствующем местном времени | Маршрут исключается |
| ROUTE-08 | Местные часы или даты в разных часовых поясах создают видимость обратного порядка событий | Порядок и длительности определяются по фактическим моментам времени с учётом часовых поясов, а не вычитанием показаний местных часов |
| ROUTE-09 | Следующий рейс вылетает раньше либо одновременно с прибытием предыдущего рейса | Такая последовательность не образует допустимый маршрут |
| ROUTE-10 | Между прилётом и следующим вылетом положительный, но очень короткий интервал | Маршрут не исключается из-за недостаточности времени на пересадку: эта проверка в MVP отсутствует |
| ROUTE-11 | Прилёт и следующий вылет происходят в разных аэропортах одного промежуточного города | Это одна промежуточная остановка; маршрут допускается без проверки времени на переезд; пользователь видит предупреждение о смене аэропорта |
| ROUTE-12 | Остановка длится более 72 часов, маршрут укладывается в окно и проходит проверку привлекательности | Маршрут допускается: отдельного лимита длительности остановки нет |
| ROUTE-13 | Остановка приходится преимущественно на ночь | Само по себе это не исключает маршрут |
| ROUTE-14 | На остановке нет времени для прогулки | Само по себе это не исключает маршрут; обязательного выхода в город нет |

Длительность остановки — фактически прошедшее время между прибытием в промежуточный город и следующим вылетом из него. Время на аэропортовые процедуры и дорогу не вычитается. Общая длительность маршрута — время от первого вылета до конечного прибытия, включая все остановки.

## 3. Отбор по туристической привлекательности

Город проходит проверку, если его оценка **не ниже `T`**. Проверка применяется отдельно к каждой остановке длительностью от 12 часов включительно.

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| CITY-01 | Остановка длится 11 часов 59 минут, оценка ниже `T` | Оценка города не препятствует включению маршрута |
| CITY-02 | Остановка длится ровно 12 часов, оценка ниже `T` | Маршрут исключается |
| CITY-03 | Остановка длится от 12 часов, оценка равна `T` | Остановка проходит проверку |
| CITY-04 | Остановка длится от 12 часов, оценка выше `T` | Остановка проходит проверку |
| CITY-05 | Несколько остановок длятся от 12 часов; хотя бы одна имеет оценку ниже `T` | Исключается весь маршрут, даже если он дешевле остальных |
| CITY-06 | Скрипт не отвечает для города остановки от 12 часов | Используется оценка 0 и обычное сравнение с `T`. При `T > 0` маршрут исключается |
| CITY-07 | Скрипт не отвечает для города остановки короче 12 часов | Отсутствие оценки не препятствует включению маршрута |
| CITY-08 | Есть допустимый прямой рейс | Проверка промежуточных городов к нему не применяется |

Для контрольных примеров можно использовать тестовое значение `T = 60` и оценки 59, 60 и 61. Это данные теста, а не согласованный рабочий порог. Проверки отбора используют заданные оценки и не подтверждают качество самой методики расчёта привлекательности.

## 4. Стоимость и валюта

Для каждого предложения используется минимальный доступный тариф экономкласса для одного взрослого с обязательными сборами. Дополнительный багаж к тарифу не добавляется.

Рассчитанная стоимость — сумма известных цен билетов и известных визовых расходов, приведённых к рублям. Цена единого билета учитывается один раз, даже если он покрывает несколько рейсов. Обязательные сборы, уже включённые в цену источника, повторно не добавляются.

Если обязательная часть стоимости неизвестна, она не увеличивает рассчитанную сумму. Это не означает, что соответствующий расход равен нулю: пользователь должен видеть неизвестную составляющую и пометку о неполной стоимости.

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| PRICE-01 | Для одного билета доступны несколько тарифов экономкласса | Используется минимальный доступный тариф с обязательными сборами |
| PRICE-02 | У выбранного тарифа нет дополнительного багажа | Багаж автоматически не докупается; в карточке отражаются условия выбранного тарифа |
| PRICE-03 | Маршрут состоит из нескольких отдельных билетов | Их стоимости суммируются |
| PRICE-04 | Один билет покрывает несколько рейсов | Его стоимость входит в сумму один раз и показывается целиком |
| PRICE-05 | Известны необходимые визовые расходы | Они входят в рассчитанную стоимость и отображаются отдельно |
| PRICE-06 | Требуются проживание или переезд между аэропортами | Их стоимость не добавляется; исключение этих расходов указано в карточке |
| PRICE-07 | Цена источника выражена в другой валюте | Для сравнения и выдачи используется пересчёт в рубли; в тесте применяется заранее заданный курс |
| PRICE-08 | Часть обязательной стоимости неизвестна | Маршрут остаётся в общей выдаче; показаны известная сумма, пометка «Полная стоимость неизвестна» и неизвестная составляющая |
| PRICE-09 | У маршрута с неполной стоимостью известная сумма ниже, чем у маршрута с полной стоимостью | Он располагается выше; отдельного штрафа или исключения из сортировки нет |
| PRICE-10 | Для маршрута требуется виза | MVP рассчитывает расходы, но не проверяет возможность въезда, транзита или своевременного получения визы |
| PRICE-11 | Цены получены в ходе поиска | Перед показом результата дополнительного запроса для перепроверки цен нет; время получения цен доступно пользователю |

Контрольные расчёты:

- Два билета по 10 000 ₽ и 15 000 ₽, известные визовые расходы 3 000 ₽: итог 28 000 ₽.
- Единый билет на два рейса стоимостью 20 000 ₽, визовые расходы 3 000 ₽: итог 23 000 ₽, а не 43 000 ₽.
- Билет за 100 единиц иностранной валюты при тестовом курсе 90 ₽ за единицу и визовые расходы 1 000 ₽: итог 10 000 ₽.
- Билеты на 20 000 ₽, стоимость необходимой визы неизвестна: показано 20 000 ₽ с пометкой о неполной стоимости. Такой вариант находится выше полностью рассчитанного варианта за 21 000 ₽.

Повторная проверка цен и гарантия сохранения цены к моменту самостоятельной покупки пользователем не входят в приёмку MVP.

## 5. Полнота, сортировка и количество результатов

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| RESULT-01 | Найдено более 10 допустимых предложений | Выдаются 10 предложений с наименьшими рассчитанными суммами известных составляющих |
| RESULT-02 | Найдено от 1 до 10 допустимых предложений | Показываются все найденные предложения; это успешный поиск |
| RESULT-03 | В контрольном наборе существует более дешёвое допустимое предложение, чем включённое в десятку | Его пропуск считается ошибкой полноты поиска |
| RESULT-04 | Предложения имеют разные рассчитанные стоимости | Они показаны по возрастанию стоимости |
| RESULT-05 | Более дешёвое предложение имеет больше остановок или более низкую, но допустимую оценку города | Оно располагается выше; число остановок и привлекательность не изменяют порядок по цене |
| RESULT-06 | Найдены предложения с одинаковыми рейсами на те же даты | Устранение дублей не выполняется; такие предложения могут занимать отдельные места в пределах десяти результатов |
| RESULT-07 | Несколько предложений имеют одинаковую рассчитанную стоимость | Допустим любой порядок между ними; дополнительный критерий сортировки не задан |
| RESULT-08 | На границе десятки несколько предложений имеют одинаковую стоимость | Допустим любой выбор из них при соблюдении лимита и включении всех строго более дешёвых предложений |

Пример проверки ограничения: в отдельном контрольном наборе есть 13 допустимых предложений со стоимостями 1 000, 2 000, …, 13 000 ₽. Ожидаются первые 10, в порядке от 1 000 до 10 000 ₽. Наличие дублей не является основанием автоматически заменить их более дорогими уникальными маршрутами.

Ограничение десятью результатами относится к выдаче. Оно само по себе не разрешает останавливать поиск на первых десяти найденных предложениях, если это приводит к пропуску более дешёвых допустимых предложений в согласованной области поиска.

## 6. Содержимое карточки маршрута

Критерий **CARD-01**: каждое предложение содержит следующие сведения.

| Группа | Обязательные сведения |
| --- | --- |
| Стоимость | Общая рассчитанная сумма в рублях; при неполных данных — пометка «Полная стоимость неизвестна» и указание неизвестной составляющей |
| Каждый рейс | Авиакомпания, номер рейса, аэропорты, местные даты и время вылета и прилёта |
| Билеты | Стоимость каждого билета; для единого билета на несколько рейсов — стоимость билета целиком |
| Визы | Визовые расходы отдельно от стоимости билетов |
| Багаж | Условия по каждому билету |
| Остановки | Промежуточные города и длительности остановок |
| Смена аэропорта | Предупреждение для каждой остановки со сменой аэропорта |
| Продолжительность | Общая длительность маршрута |
| Исключённые расходы | Указание, что проживание и переезды не включены в стоимость |
| Актуальность цен | Время получения использованных цен |

Критерий **CARD-02**: сценарий завершается показом маршрутов и стоимости. Ссылки на покупку билетов не предоставляются; покупки внутри сервиса нет.

Для проверки CARD-01 нужен как минимум один маршрут из отдельных билетов со сменой аэропорта и неизвестной составляющей стоимости, а также отдельный пример единого билета на несколько рейсов.

## 7. Завершение поиска и отсутствие результатов

| ID | Условие / действие | Ожидаемый результат |
| --- | --- | --- |
| FLOW-01 | Поиск ещё не завершён | Итоговые карточки не показываются; промежуточной выдачи нет |
| FLOW-02 | Весь поиск успешно завершён и есть допустимые предложения | Выдача появляется целиком, с учётом лимита десяти результатов |
| FLOW-03 | Весь поиск успешно завершён и допустимых предложений нет | Показано «Маршруты не найдены» с предложением изменить даты или города |
| FLOW-04 | Подходящих предложений нет | Система не расширяет даты, не меняет города и не ослабляет ограничения автоматически |

В MVP поиск выполняется синхронно. Выдача частичных результатов при незавершённом поиске не предусмотрена. Отсутствие ответа скрипта оценки города обрабатывается по CITY-06 и CITY-07.

Поведение при сбоях остальных источников, предел ожидания и условия признания поиска завершённым при ошибках пока не согласованы. Успешный поиск без вариантов и поиск, который не удалось завершить, нельзя считать одним и тем же приёмочным сценарием.

## 8. Что не требуется для приёмки MVP

- Авторизация и покупка билетов.
- Ссылки на покупку во внешних сервисах.
- Поиск туда-обратно и настройка профиля пассажира.
- Выбор пользователем конкретного аэропорта.
- Устранение дублей в выдаче.
- Подбор проживания и расчёт стоимости проживания или переездов.
- Проверка достаточности времени пересадки, включая переезд между аэропортами.
- Проверка возможности въезда, транзита и получения визы к дате поездки.
- Обязательная возможность погулять и преобладание дневного времени на остановке.
- Повторная проверка цены перед показом результата.
- Частичная или постепенно дополняемая выдача.

## 9. Открытые параметры и ограничения спецификации

| ID | Что требуется определить | На что влияет |
| --- | --- | --- |
| OPEN-01 | Рабочий порог `T` после калибровки городской метрики | Отбор в рабочей среде. Логику сравнения можно принять на тестовом пороге, но качество отбора городов ещё не подтверждено |
| OPEN-02 | Предельное время ответа после измерений прототипа; условия замера, объём данных и нагрузка | Приёмка производительности. Сейчас числового критерия нет |
| OPEN-03 | Реальные источники, их покрытие, связь городов с аэропортами и согласованная область поиска | Полнота и корректность поиска на реальных данных |
| OPEN-04 | Источник валютного курса и правила округления | Точные денежные расчёты и порядок близких по стоимости предложений. Контрольные примеры выше не требуют спорного округления |
| OPEN-05 | Обработка ошибок и предел ожидания источников рейсов, цен и визовых расходов; критерий отсутствия ответа скрипта оценки | Завершение синхронного поиска и сценарии сбоев. Значение оценки при отсутствии ответа уже согласовано: 0 |
| OPEN-06 | Правила определения необходимых визовых расходов, включая повторные посещения стран | Полнота расчёта визовой составляющей. В контрольных тестах необходимые расходы заданы заранее |
| OPEN-07 | Допустимый возраст данных источников, если используются ранее полученные цены | Актуальность результатов. Отказ от повторного запроса сам по себе не задаёт срок актуальности |

Максимальное окно поиска пока равно 30 календарным дням. Оно может быть пересмотрено после измерений прототипа; до отдельного решения приёмка использует именно 30 дней.

## 10. Фиксация результатов приёмки

Для каждого критерия фиксируются версия сборки, версия контрольных данных, использованные параметры, фактический результат и статус: «пройден», «не пройден» или «не проверен». Для отклонений сохраняется описание и воспроизводимый пример.

Прохождение функциональных сценариев на контрольном наборе подтверждает согласованную логику MVP. Оно не заменяет проверку интеграций на реальных источниках, калибровку городской метрики и измерение производительности. Непроверенные пункты и открытые параметры указываются явно в результате приёмки.
